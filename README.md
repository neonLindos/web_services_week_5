| Работа | Проект | Страница | Решение |
|---|---|---|---|
| Домашняя | TaskManagerClient | http://localhost:5101 | [Задачи](homework/README.md) |

Все три клиента реализуют GET списка и записи по ID, POST, PUT и DELETE.

## Запуск

Перейдите в папку нужной работы и выполните:

```powershell
cd homework   # или lab, prac
dotnet run
```

Вместе с клиентом поднимается встроенный учебный API на порту 5100, если там ещё ничего не работает, и
останавливает его при выходе. `Ctrl+C` завершает клиент и API. Нужен SDK .NET 10.
Запускайте один клиент за раз. `make` в папке работы делает то же самое;
`make homework`, `make lab`, `make prac` из этой папки — тоже.
Если по адресу `Api:BaseAddress` уже работает другой API, клиент использует его.
Каждая работа самостоятельна: её папку можно открыть (`.csproj`) и запустить отдельно от остальных.

Клиент MVC → именованный HttpClient → отдельный API на порту 5100 → данные
в памяти. Браузер обращается к MVC, а MVC — к API; CORS для этого сценария
не требуется. Данные сбрасываются при перезапуске API.

Методичка не выдаёт сам внешний API, а API предыдущих модулей не совпадают с этими
клиентами по моделям и формату ответов. Поэтому в каждую работу встроен свой учебный API
(`Api/DemoApi.cs`): он работает как отдельный HTTP-сервер на порту 5100 внутри процесса клиента
и отдаёт ресурс этой работы — `/api/tasks`, `/api/products` или `/api/students` — с операциями по `/{id}`.
POST возвращает 201 с Location, PUT/DELETE — 204. Входные данные проверяются через DataAnnotations
(400 при ошибке). Клиент и API общаются только по HTTP и JSON, как с настоящим внешним API.

Адрес внешнего API задаётся в `Api:BaseAddress` каждого клиента; значение
должно быть абсолютным URL с завершающим `/`. Код обработки ответов
(`Services/ApiService.cs`, `Services/ApiResult.cs`) лежит в каждой работе отдельно,
поэтому любую папку можно передать целиком без остальных.

## Адреса страниц и эндпоинты

Для работы в браузере открывайте клиент:

| Работа | Главная страница | Пример страницы записи |
|---|---|---|
| Домашняя — задачи | http://localhost:5101 | http://localhost:5101/Task/Details/1 |
| Лабораторная — товары | http://localhost:5102 | http://localhost:5102/Product/Details/1 |
| Практическая — студенты | http://localhost:5103 | http://localhost:5103/Student/Details/1 |

На порту **5100 работает API**. Маршрут `/` у него отсутствует: открытие
http://localhost:5100 может показать пустую страницу с ответом 404.
Чтобы увидеть данные API в браузере, откройте один из GET-эндпоинтов:

- Задачи: http://localhost:5100/api/tasks
- Товары: http://localhost:5100/api/products
- Студенты: http://localhost:5100/api/students

API возвращает JSON. Все пути в таблице ниже относятся к адресу `http://localhost:5100`.
`{id}` замените числовым ID записи.

| Метод | Задачи | Товары | Студенты | Назначение | Успех |
|---|---|---|---|---|---|
| GET | `/api/tasks` | `/api/products` | `/api/students` | Получить список | 200, JSON-массив |
| GET | `/api/tasks/{id}` | `/api/products/{id}` | `/api/students/{id}` | Получить запись по ID | 200, JSON-объект |
| POST | `/api/tasks` | `/api/products` | `/api/students` | Создать запись | 201, объект и заголовок Location |
| PUT | `/api/tasks/{id}` | `/api/products/{id}` | `/api/students/{id}` | Изменить запись | 204, без тела |
| DELETE | `/api/tasks/{id}` | `/api/products/{id}` | `/api/students/{id}` | Удалить запись | 204, без тела |

GET по ID, PUT и DELETE возвращают **404**, если запись не найдена.
POST и PUT возвращают **400**, если входные данные не прошли проверку;
для PUT значение `id` в JSON должно совпадать с ID в URL.
При создании ID назначается API автоматически.

Страницы клиента используют пути `/{контроллер}/{действие}/{id?}`:
контроллер — `Task`, `Product` или `Student`; действия — `Index` (список),
`Details` (подробности), `Create` (добавление), `Edit` (изменение),
`Delete` (подтверждение удаления). Сохранение форм выполняется через POST
к клиенту, а клиент отправляет соответствующий POST, PUT или DELETE в API.

## Проверка без запуска серверов

Папка `checks/` — необязательные проверки, отдельные от работ (сами работы от неё не зависят):

```powershell
dotnet run --project checks/checks.csproj
```

Проверено: сборка Razor и C#, 177 утверждений в консольных проверках.
Сервисы клиентов проверяются с подставным HTTP-обработчиком:
методы, URL, сериализация, 200/201/204, 400/404/500 и другие ошибки,
неверный/пустой JSON, недоступность сети, тайм-аут.
Встроенный API каждой работы проверяется на тестовом сервере в памяти: CRUD, 404, 400
при пустых данных и неверном JSON, Location, назначение Id сервером, и что API слушает
только адрес из `Api:BaseAddress`, а не адрес клиента.
Слушающие порты не открываются. Проверки не заменяют сквозную проверку форм,
HTTP-конвейера MVC и антиподдельных токенов в браузере.

## Проверка в браузере и скриншоты

В соответствии с правилами репозитория серверы запускает пользователь.
Фактических скриншотов в решении пока нет. Для домашней работы методичка
требует их приложить; лабораторную нужно продемонстрировать преподавателю.

После запуска выбранного клиента (`dotnet run`, API поднимается вместе с ним):

1. Откройте список и снимите таблицу с исходными записями.
2. Найдите запись с ID `1`, проверьте все поля на странице подробностей.
3. Создайте запись. Для товара: «Монитор», описание «Учебный», цена `45000`,
   количество `2`. Для студента: «Алексей Сидоров», `SE-301`, курс `3`,
   `alex@example.com`. Для задачи: «Подготовить отчёт», описание «Модуль 05».
4. Снимите заполненную форму и список после успешного добавления.
5. Измените запись: у товара цену и количество, у студента группу и Email,
   у задачи название, описание и флажок выполнения. Снимите результат.
6. Откройте удаление и сначала нажмите «Отмена»: запись должна остаться.
   Затем подтвердите удаление и снимите обновлённый список.
7. Найдите ID `999999`: должно появиться понятное сообщение о ненайденной записи.
8. Попробуйте сохранить пустое обязательное поле, отрицательную цену или
   неверный Email. Данные не должны быть отправлены в API.
9. Остановите API и обновите страницу клиента: появится сообщение о недоступности.

Скриншоты домашней работы можно сохранить в `homework/screenshots/`.
Сценарии ответов 400 и 500 внешнего API покрыты автоматическими проверками;
для ручной демонстрации этих ответов нужен API, возвращающий соответствующий статус.
