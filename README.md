# CSE5032 · Модуль 05 — вызов Web API из ASP.NET Core

**Работу выполнил:** Рябинин Максим

Пятая тема курса **«Разработка веб-сервисов»**: клиентские приложения ASP.NET Core MVC, которые обращаются к внешнему Web API через `HttpClient`. Клиент создаётся именованной регистрацией `AddHttpClient` и берётся из `IHttpClientFactory`, запросы GET / POST / PUT / DELETE отправляются в API, а ответы 200, 201, 400, 404 и 500 разбираются так, чтобы приложение не падало и показывало понятное сообщение.

## Как запустить

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download) или более новый. Можно открыть [Module05.sln](Module05.sln) в Visual Studio либо работать из терминала.

Сначала в отдельном терминале поднимите учебный API — без него клиенты покажут сообщение о недоступности:

```powershell
dotnet run --project api/DemoApi.csproj
```

Затем нужный клиент, каждый в своём терминале:

```powershell
dotnet run --project homework/TaskManagerClient.csproj
dotnet run --project lab/ProductClient.csproj
dotnet run --project prac/StudentClient.csproj
```

Каждая команда работает до Ctrl+C, поэтому не вставляйте их в один терминал, если хотите открыть несколько клиентов сразу.

| Приложение | Адрес |
|---|---|
| Учебный API | http://localhost:5100 |
| homework — задачи | http://localhost:5101 |
| lab — товары | http://localhost:5102 |
| prac — студенты | http://localhost:5103 |

Браузер обращается к MVC-клиенту, а клиент — к API, поэтому CORS в этом сценарии не нужен. Адрес API задаётся в `appsettings.json` каждого клиента ключом `Api:BaseAddress`; значение должно быть абсолютным URL с завершающим `/`. Учебный API хранит данные в памяти — после его перезапуска изменения сбрасываются. HTTP используется для локальной демонстрации, для развёртывания нужен HTTPS.

Учебный API добавлен, чтобы работу можно было запустить одной командой: модели и оболочки ответов из предыдущих модулей не полностью совпадают с требованиями этих клиентов. Он отдаёт `/api/tasks`, `/api/products`, `/api/students` и операции по `/{id}`; POST возвращает 201 с заголовком Location, PUT и DELETE — 204, а входные модели проверяются `[ApiController]` и DataAnnotations.

## Структура

Каждая подпапка `homework/`, `lab/`, `prac/` — самостоятельный проект:

- `.docx` в корне — методичка от преподавателя, как выдана;
- `Модуль_05_*.md` — та же методичка в Markdown;
- `README.md` — решение: что реализовано, ответы на контрольные вопросы, итоговая таблица;
- `Models/` — модель данных MVC-клиента;
- `Services/` — интерфейс сервиса API и его реализация на `IHttpClientFactory`;
- `Controllers/` и `Views/` — страницы списка, подробностей, формы и удаления.

Модели клиентов отделены от моделей API: приложения связаны только JSON по HTTP. Результаты сборки и локальные базы исключены через `.gitignore`.

## Проверка

Из корня репозитория:

```powershell
dotnet build Module05.sln
dotnet run --project checks/checks.csproj
```

Проверки используют настоящий код API-сервисов с подставным HTTP-обработчиком: методы, URL, сериализация, коды 200, 201 и 204, ошибки 400, 404 и 500, неверный и пустой JSON, недоступность сети и тайм-аут. Отдельно проверены CRUD и заголовок Location у контроллеров учебного API, а также ограничения моделей. Слушающие порты при этом не открываются.

## Проверка в браузере и скриншоты

Проверки не заменяют сквозной прогон форм, конвейера MVC и антиподдельных токенов в браузере. После запуска API и выбранного клиента:

1. Откройте список и посмотрите исходные записи.
2. Найдите запись с ID `1` и проверьте все поля на странице подробностей.
3. Создайте запись. Для товара: «Монитор», описание «Учебный», цена `45000`, количество `2`. Для студента: «Алексей Сидоров», `SE-301`, курс `3`, `alex@example.com`. Для задачи: «Подготовить отчёт», описание «Модуль 05».
4. Убедитесь, что запись появилась в списке.
5. Измените запись: у товара цену и количество, у студента группу и Email, у задачи название, описание и флажок выполнения.
6. Откройте удаление и сначала нажмите «Отмена» — запись должна остаться. Затем подтвердите удаление.
7. Найдите ID `999999`: появится сообщение о ненайденной записи вместо ошибки приложения.
8. Попробуйте сохранить пустое обязательное поле, отрицательную цену или неверный Email — данные не должны уйти в API.
9. Остановите API и обновите страницу клиента: появится сообщение о недоступности сервиса.
